# Audio

Every audio file the app can play is named in exactly one place:
`AdhanAsset` in
`Packages/IhsanNotifications/Sources/IhsanNotifications/AdhanSoundCatalog.swift`.
No call site anywhere refers to a file name. To swap a recording in,
drop the file into `ihsan/Resources/Adhans/` and change one line there.

## What ships today

| Constant | File | What it is |
| --- | --- | --- |
| `AdhanAsset.chime` | `ihsan-chime.caf` | 8s. One struck bowl with a softer echo. **Synthesised placeholder.** Also the gentle-wake tone, via `AdhanAsset.nightWake`. |
| `AdhanAsset.chimeDawn` | `ihsan-chime-dawn.caf` | 24s. The same bowl struck four times, rising. Offered for Fajr only. **Synthesised placeholder.** |
| `AdhanAsset.takbirat` | `ihsan-takbirat.caf` | **Absent.** Set → Adhan does not offer the option until the file is present; a choice stored by an earlier build plays the chime and reads as the chime. |
| `AdhanAsset.fullAdhan` | `ihsan-adhan-full.m4a` | **Absent.** Set → Adhan's "The full call" section and the notification's Play action appear only once it is; the About audio credit appears once either this file or `ihsan-takbirat.caf` is bundled. |

The two chimes are generated by `generate-placeholders.py` from sine
partials only — no sample, no recording, no license question. Run it
and convert:

```bash
python3 docs/audio/generate-placeholders.py
afconvert ihsan-chime.wav      -d LEI16@44100 -c 1 -f caff ihsan-chime.caf
afconvert ihsan-chime-dawn.wav -d LEI16@44100 -c 1 -f caff ihsan-chime-dawn.caf
```

The script also writes `ihsan-adhan-full-placeholder.wav`; that file is
a development aid for exercising `AdhanPlayer` and must not be bundled
— a synthesised "full call" in the shipping app would be a broken
feature, not a placeholder.

Keep this folder free of anything that is not a shipping asset — the
app target syncs `ihsan/` wholesale, so a stray script would be copied
into the bundle.

## What a real recording must satisfy

**Notification tones** (`chime`, `chimeDawn`, `takbirat`) are played by
iOS while the app is not running:

- Core Audio Format (`.caf`)
- **30 seconds maximum** — iOS ignores a longer file, and the
  notification then arrives with no sound at all
- 44.1 kHz, 16-bit; mono or stereo
- Must sit at the top level of the app bundle (anything in
  `ihsan/Resources/Adhans/` does)

**The full adhan** (`fullAdhan`) is played by `AdhanPlayer` through
AVAudioPlayer and has no length limit. Any format AVFoundation reads;
`.m4a` keeps the binary small.

## Sourcing and licensing

Audio must be CC-licensed or explicitly licensed for App Store
distribution, and the license has to cover redistribution inside an
app, not just personal use. Widely available recitations — Mishary
Rashid Alafasy, Saud Al-Shuraim, Abdul Rahman Al-Sudais — each need
their license verified per source; "widely available" is not a license.

Record every file's source and license in `LICENSES.txt` in this folder
before shipping. App Review spot-checks audio provenance.

## Fallback behaviour

`AdhanSoundCatalog.options(for:using:)` checks the bundle and leaves
out any option whose file is missing, so Set never offers a muezzin it
cannot play. `resolvedFileName(using:)` handles a choice stored by an
earlier build: it falls back to the chime — never to the iOS tri-tone,
which would sound like a different app — and `effectiveChoice(using:)`
makes the row read "Chime" so the substitution is visible rather than
mysterious. `.silent` resolves to no sound at all; the banner still
arrives.
